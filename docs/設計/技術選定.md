# 技術選定

## 概要

シンプル ToDo アプリで使用する言語・フレームワーク・ミドルウェアの選定理由を記録する。

## 選定一覧

| レイヤー | 採用技術 | バージョン |
|---|---|---|
| バックエンド言語 | Python | 3.11 以上 |
| バックエンド FW | FastAPI | 最新安定版 |
| ASGI サーバー | Uvicorn | 最新安定版 |
| フロントエンド CSS | Tailwind CSS | CDN（最新） |
| フロントエンド JS | Alpine.js | CDN（最新） |
| データベース | SQLite | Python 標準（sqlite3） |

## 各技術の選定理由

### FastAPI

- Python で REST API を最小限のコードで構築できる
- 自動で API ドキュメント（Swagger UI）が生成されるため、動作確認が容易
- 型ヒントによるバリデーションが標準で組み込まれている
- 静的ファイルの配信も対応しており、HTML の配信を別途サーバーで行う必要がない

### Tailwind CSS（CDN）

- `<script>` タグ 1 行で導入できるため、ビルド環境が不要
- ユーティリティクラスで素早くスタイリングできる
- 今回のシンプルな 1 画面 UI に対して十分な機能を持つ

### Alpine.js（CDN）

- `<script>` タグ 1 行で導入できるため、ビルド環境が不要
- Vue.js に近い直感的な記法で動的 UI（リスト更新・チェックボックスなど）を実装できる
- 今回の規模（1 画面・CRUD のみ）には十分な機能を持つ

### SQLite

- Python 標準ライブラリ `sqlite3` で使えるため、追加インストール不要
- ファイルベースで動作するため、DB サーバーの起動が不要
- 個人利用・低負荷のアプリに適している

## 採用しなかった選択肢

| 技術 | 採用しなかった理由 |
|---|---|
| React / Vue.js | ビルド環境が必要で構成が複雑になる。今回の規模には過剰 |
| PostgreSQL / MySQL | サーバー起動が必要。個人利用には過剰 |
| Django | フルスタック FW でシンプルな API には機能過多 |
| Flask | FastAPI に比べてバリデーションや型サポートが弱い |
